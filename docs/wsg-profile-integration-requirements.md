# Optional WSG profile integration — confirmed requirements

This document records the integration contract, separate from the live-weight PR and the editor layout. It does not introduce new flight behavior.

- WSG is opt-in; published profiles and matching references must be fetched anonymously, without login, session or API key. Local-only editing and explicit local imports must work offline.
- Match an active simulator aircraft to an exact WSG variant only with unambiguous add-on and variant evidence, and confirm the canonical ordered flap labels/handle mapping. Do not match by an ambiguous title or reuse another aircraft's last profile. Preserve explicitly bound local profiles and provide Custom profile… for unmatched aircraft (saved local profile or local JSON); the desktop and cockpit must use the same resolved selection.
- After an exact WSG match, resolve each supported value from the published default plus the pilot's local field-level overrides. Untouched fields continue following the published defaults when they change. A local override must remain distinct from a snapshot of the published profile. No operation writes a public profile or requires a WSG account.
- Persist overrides under stable canonical variant identifiers. Transition-specific overrides additionally require stable ordered transition identity (the two canonical positions/handles), not row number or label alone. Never transfer overrides between variants or silently reapply them to changed flap mappings; retain unmatched overrides as local data and surface the incompatibility.
- Reset to WSG defaults removes the relevant local overrides and re-resolves the current published fields. Missing defaults remain missing, not invented values. Do not relabel the weights of default trigger values if personal weight anchors change; validate compatible curves before using them.
- The existing public catalog provides live-weight anchors and IAS thresholds; it may omit both stall IAS endpoints and it provides TAS VNE, not an IAS upper bound. Published exclusions also require compatible display grouping/semantics. The WSG renderer uses the published TAS number only as visual geometry (not an IAS limit); without a usable number it derives a visual extent from the included IAS dividers. No LOW or FAST warning is generated without a corresponding explicit IAS limit. Hidden transitions merge adjacent cells while retaining the precise native detent. Stall IAS is enabled only for the exact loaded weights and detent preceding the first included transition; changing this context requires an explicitly confirmed pair or suppresses the stall indication.
- The later approved workflow is one coherent follow-up PR: visible main app with simple Profile mode (Auto-detect by default or Manual), current source/profile, optional Auto fallback (None by default), and Manual active-profile picker. Persist the manual choice independently of fallback and explicit per-aircraft assignment. Do not guess an aircraft. Label fallback explicitly. Profile creation/import, simulator mapping, weights, and speeds belong in a separate advanced Settings → Profiles window, not the main controls.
- An adjusted WSG profile may locally use Manual ballast; the local mode must not remove or alter its published reference weights or association. Reset clears all local overrides, including ballast mode. WSG-published data continues requiring both weights and stores no ballast choice. New custom profiles may choose manual or live mode as in PR #1.
- Implementation status: the editor and read-only public preview are locally stacked after PR #1, with exact-variant matching and safe unmatched behavior. The selection-policy and field-overlay models are locally implemented; the interim editor can save/reset personal adjustments and the runtime can resolve manual/fallback selections, the live Electron shell has separate native Profiles editor and simple selection controls (tested with mocked live aircraft), but assembling the final main vs optional external-panel layout with PR #3 is pending; exact WSG profiles now activate with the WSG-specific display semantics and personal local overrides. The visible main/separate external window lifecycle is independently under review in PR #3. Integrate that lifecycle before shipping the follow-up rather than reintroducing duplicate telemetry/window ownership. No follow-up public PR should include unrelated PR #1 or #3 changes in its review diff.
